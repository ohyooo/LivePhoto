# 真实设备验收清单

这是待执行的验收方法和空白记录，不是兼容性名单。云端 CI、模拟器、虚拟显示、合成素材和文件解析各有用途，但不证明某台消费设备的相册、显卡、音频设备或浏览器能完整使用动态照片。

## 开始前

1. 固定本轮版本：记录源码提交、构建号、平台和已验证产物标识。网页记录实际打开的地址及部署产物的提交或运行号，不用仓库中较新的提交代替网页版本。
2. 每一条记录只对应一个版本、设备、系统、相册或浏览器、协议 profile 和导入路径。换相册、升级系统、换导入路径或开启硬件加速后另建一条，不覆盖旧结论。
3. 用一份已知可播放且含可辨认声音的合法来源素材作对照，再用另一份非动态照片作负对照。需要确认关键帧时，用动作明显的短视频和可辨认的封面。合成文件、未编辑的原厂文件、应用生成的文件分别记录，不能互相代替。
4. 原片、输出及比对材料保存在测试者控制的本地目录。不要把照片、视频、截图、文件名、路径、位置数据、设备序列号或私人素材的哈希提交到仓库、公共 issue 或 CI。可公开的是匿名编号、是否字节不变和经过清理的结构化错误码。页面与测试不要求远程接入测试设备。

## Android 与相册

| 测试 | 操作 | 单独验收的结果 |
| --- | --- | --- |
| 原厂对照 | 在同一台真机的目标相册打开未编辑的原厂动态照片；记录传入方式 | 相册是否识别为动态照片、是否播放、是否听见预期声音、静态封面是否与对照一致 |
| 应用生成 | 选取一个明确支持的 JPEG＋MP4 profile（OPPO/OnePlus、Google V2 或 Google V1），通过 LivePhoto 生成并保存；在目标相册打开另存文件 | 分别记录应用保存、相册动态识别、实际播放、声音、封面和可辨认的 key 位置。检查原文件未改、重启相册后结果仍可见 |
| 导入路径对照 | 在相册已确认支持相同 profile 后，再通过系统文件入口或另一种想验证的路径导入同一份测试输出 | 路径单独记录；文件管理器可播放、文件名可见或相册可识别均不等于声音与 key 通过 |
| 安全拒绝 | 使用普通照片或能力表明确不支持的素材，执行对应检查或写入操作 | 检查/解析普通照片不冒充动态照片；不支持的写入返回结构化错误，不新增输出、不覆盖原片 |

应区分系统供应商相册与其它相册 App；不要用一个 App 的结果推断另一个。分支 CI 的测试签名不能作为已安装正式签名 APK 的更新证据。不为验收而卸载已有 App 或清空相册。

## iOS 只读 Core

- 目前能验证的是 `LivePhotoCore` 在真实 arm64 iPhone 中由 Swift 宿主链接并调用。用普通照片、显式匹配的图＋视频、故意不匹配的配对各执行一次，分别记录调用结果、是否识别为动态配对、错误码，以及输入是否不变。记录真机架构、iOS 版本和框架产物身份。
- 当前没有 iOS App 或 Photos 写入集成。可以另记系统 Photos 打开合法对照素材的表现，但不能据此认定 LivePhoto 写入、导入或相册兼容已通过。Apple Silicon 模拟器上的 Swift 运行也不能代替真机。

## 桌面实体 GPU 与音频

在目标 GUI 系统使用对应便携包。记录系统版本、GPU/驱动、实际渲染设备、显示器缩放方式、音频输出类型和 JavaFX/应用版本。必须明确是硬件还是软件渲染；不知道则记录未知。

1. 打开已知可播放且含声音的短视频，记录首帧、连续播放、拖到其他时间、暂停后恢复、可听见的声音及音量/静音行为。
2. 进入并退出全屏两次，确认返回编辑器后选材与状态保留；再在宽高不同的素材上重复。检查画面空白、遮挡或残影是否可见，并记下首次出现的操作，不用单张截图推断整个播放正常。
3. 在播放状态关闭窗口，重新打开应用并加载同一份原片。确认无挂起、旧播放不延续、原片不变；已有输出不应被覆盖。
4. 如要验证不同 GPU、驱动、显示缩放、蓝牙/有线音频设备或设备切换，逐组合增加记录。看得到播放进度不能证明设备有声音；系统对照播放器也无声时，先记为环境条件未满足，不能按通过处理。

## 浏览器真实设备

公开站点在实际设备上单独记录浏览器版本、系统、硬件加速是否启用、窗口类型和站点部署身份。验收首次打开、选择素材、生成后真实下载、从全屏返回，以及播放器是否有遮挡或残影。录入浏览器端结果时不要附带私有素材。下载与文件完整性通过不代表把输出导入本机相册后仍能动态播放；相册行为用上面的设备记录另测。
